# Bib Formatter

.bib と PDF のメタデータを biblatex に統一し、`Year_Authors_Title` のファイル名を作るブラウザ用ツールです。ビルド結果は `dist/index.html` の1ファイルで、保存すればオフラインでも動きます。変換処理はブラウザ内で行います。

公開先: https://sasakiy84.github.io/bib-formatter/

## 使い方

.bib を貼り付けるかファイルを開き、「biblatex に変換」を押します。Ctrl+Enter / ⌘+Enter でも変換できます。結果はコピーまたは .bib として保存できます。ファイル名は文献ごとに選択・コピーできます。

.bib のダウンロード名は `_引用キー.bib`（例: `_Linell2019.bib`）です。複数文献の場合は先頭のキーを使い、キーが空なら `_references.bib` にします。

ヘッダーの「LLM用プロンプト」タブから、引用表記や参考文献リストなどを biblatex に整えるためのプロンプトをコピーできます。利用するLLMに貼り付け、末尾の「書誌情報」を置き換えて使います。「変換」タブに戻ると入力・編集内容は保持されます。

右側の「変換した biblatex」は直接編集できます。タイトル・著者・出版年を変更するとファイル名も更新され、コピー・保存には編集した内容が使われます。構文が編集中の場合は入力を保持し、修正が済むまでコピー・保存を無効にします。左側への貼り付け時に右側が空なら自動変換します。右側に内容がある場合は保持し、「biblatex に変換」を押したときだけ置き換えます。

右側に文献が1件だけある場合は、タイトル・著者・出版年月日・掲載誌・会議名・出版社・巻号・ページ・DOI・URL などの追加ボタンを表示します。追加すると空のフィールドが入り、値の入力位置にカーソルが移動します。追加済みのフィールドのボタンは表示しません。

ファイル名には著者の姓を最大3人まで含め、4人以上なら `et-al` を付けます。著者がなければ編者を使います。日本語の姓名を分ける場合は `姓, 名` と記述してください。英語の名前・タイトルの空白はハイフンになります。日本語は保持し、拡張子を含まない名前を UTF-8 で240バイト以内に収めます。

例: `2024_Smith-Jones-Lee-et-al_An-English-Title`

## URL からの入力

`bibtex` クエリパラメータに URL エンコードした BibTeX を渡すと、入力欄へ読み込み、自動変換します。日本語・改行・記号は `URLSearchParams` または `encodeURIComponent` でエンコードしてください。

```js
const url = new URL('https://sasakiy84.github.io/bib-formatter/');
url.searchParams.set('bibtex', '@misc{, author={山田, 太郎}, title={研究}, year=2026}');
console.log(url.href);
```

パラメータが空なら何も入力しません。構文に誤りがある場合は入力を保持してエラーを表示します。URL経由の入力は、クエリとしてページの配信元にも送られます。

## PDF からの変換

同じファイル選択欄で PDF を開くと、メタデータから biblatex とファイル名を自動生成します。生成した bib は左右の欄に入り、右側で編集・コピー・保存できます。右側のテキストエリア付近にある日本語の「文献種別」を選んで「種別を変更」を押すと、bib の入力・出力の両方に反映されます。博士論文・修士論文では学位種別も設定します。PDF の引用キーも、第一著者の姓と出版年がそろえば `山田2026` のように作成します。分からない場合は空欄のままにします。

`pdf-lib` で PDF の文書情報と XMP ストリームを読み取り、`fast-xml-parser` で XMP を解析します。XMP のタイトル・著者・出版日・掲載誌・DOI を優先し、LaTeX などの作成ツールが残した初期値は採用しません。不足分を PDF Info の Title / Author / PublicationDate / PublicationYear / Year / Journal / PublicationName / DOI で補います。XMP の複数著者は順番を保持します。Info の Author はセミコロンまたは `and` を区切りとして扱います。「姓 名, 姓 名」のような日本人著者はカンマで分割し、「姓, 名」に統一します。英語の「姓, 名」のカンマは保持します。

掲載誌があれば「雑誌論文」、なければ「その他・未分類」として作成します。文献種別や著者の区切りを含め、生成内容を確認してください。出版日がなければ年は補わず、ファイル名には `nd` を使います。PDF の作成日・更新日・一般的な Dublin Core の date を出版年には使いません。メタデータ自体がない PDF でも、欠落項目を表示し、編集用の bib を生成します。

PDF は埋め込みメタデータだけを読み取ります。1ページ目の見出しからの推定、OCR、外部サービスへの照会は行いません。不足項目は右側で補完してください。PDF はサーバーへ送信されず、オフライン版でも同じ処理を利用できます。

## 変換ルール

入力側の「言語」で日本語・英語・その他を選べます。変換時に各文献へ `language = {japanese}` または `language = {english}` を設定します。「その他」では言語名を指定でき、未入力なら `language = {}` とします。選択した言語は既存の language より優先します。日本語では「姓 名」の著者表記を「姓, 名」に整え、英語ではBibTeXの人名表記を使います。PDF取り込みにも同じ言語設定を適用します。

- 文献順を保持し、種別・標準フィールド名は小文字、値は波括弧、フィールド順は固定にします。LaTeX・数式・大文字保護は保持します。
- `journal → journaltitle`、`address → location`、`school → institution`、`archiveprefix → eprinttype`、`primaryclass → eprintclass` を変換します。両方ある場合は biblatex 側を優先し、値の相違を表示します。
- `conference → inproceedings`、`techreport → report`、`phdthesis / mastersthesis → thesis`、`electronic / www → online` を変換します。学位種別を `type` に残します。
- 数値の年・月・日は `date` に統合します。既存の `date` を優先します。変換できない年月日は保持して確認を促します。日付の実在性や文献情報の正確さを照合するツールではありません。
- DOI の URL 接頭辞を取り除き、数値のページ範囲を `--` に統一します。
- 著者・編者・翻訳者・タイトル・出版情報・識別子・URL・アクセス日など、引用に使うフィールドを許可リストで保持します。保持対象は `src/formatter.ts` の `fieldOrder` と `src/field-actions.ts` の `supportedFields` にあります。`_` で始まる独自フィールドはすべて保持します。
- `abstract`、`keywords`、`file`、`note`、管理ソフトのメタデータなど、許可リストにないフィールドは削除します。crossref・xref・xdata・related・relatedtype・relatedoptions・relatedstring・entryset・ids も削除します。文献間参照の解決や他の文献からの情報の継承は行いません。
- 引用キーは、既存のものも変換時に第一著者の姓＋出版年に統一します（例: `Linell2019`）。`incollection` だけは開始ページを末尾に追加します（例: `Smith2024p123`）。ページが不明なら付けません。著者または年がなければ既存キーを保持し、元から空欄なら空欄のままにします。編者を著者の代わりには使いません。同じキーになる文献がある場合も空欄を保持し、重複を表示します。
- `@string` は展開し、`@preamble` は保持し、コメントは除きます。構文エラーと引用キーの重複は変換を中止します。未知の文献種別は保持して確認を促します。
- 著者・編者・タイトル・年の欠落、ファイル名の重複を表示します。文献種別ごとの追加候補は分類しますが、入力値の妥当性や必須項目の充足を厳密に検証するものではありません。

## 開発

Bun 1.4.4 を使用します。フレームワークと CSS ライブラリは使わず、HTML の標準フォームと小さな CSS で構成しています。BibTeX の構文解析には Better BibTeX for Zotero のパーサー `@retorquere/bibtex-parser` を使います。

```sh
bun install --frozen-lockfile
bun run typecheck
bun run test
bun run build
bun run serve
```

ブラウザ検証:

```sh
bunx playwright install chromium
bun run test:e2e
# システムの Chromium を使う場合:
CHROMIUM_PATH=/usr/bin/chromium bun run test:e2e
```

変換関数は Bun のテストで英語・日本語の論文、書籍、学位論文と、実際に生成した英語・日本語 PDF、圧縮 XMP、メタデータの欠落・破損などを検証します。Playwright ではデスクトップ・モバイル幅で変換、ファイル入出力、コピー、エラー表示、オフライン利用を検証します。テスト用の文献データには検証用の架空レコードも含まれます。

## 公開

`main` への push で GitHub Actions が型検査・テスト・ビルドを行い、成功した単一 HTML を GitHub Pages に公開します。リポジトリの Pages の公開元は GitHub Actions に設定します。

## 機械学習モデルの検討

ブラウザでの文献情報抽出の候補・配布容量・日本語対応・トレードオフは [調査資料](docs/browser-model-research.md) にまとめています。モデルはまだ組み込んでいません。

## 種別ごとのフィールド操作

文献1件のとき、右側のフィールド操作を「必須」「任意」「削除」に分けます。必須・任意には存在しないフィールドだけを表示します。空のフィールドも追加済みとして扱います。「著者または編者」「DOI・eprint・URLのいずれか」のような条件を扱い、年月日は標準化先の `date` を追加します。`year` があれば日付は追加済みとして扱い、`year` / `month` / `day` は個別の追加候補には出しません。

種別に合わないという理由だけではフィールドを自動削除しません。「削除」から選んだフィールドだけを削除します。`_` 始まりの独自フィールドは不適合にしません。未知の種別ではスタイル固有の規則を決めつけず、削除候補を出しません。任意の追加候補は基本項目と `_tags` / `_notes` に絞ります。編者A/B/C、出版状況、電子版分類などの専門的な追加ボタンは表示しません。既存の有効なフィールドは保持します。

定義は [biblatex公式マニュアルの標準スタイル向け一覧](https://github.com/plk/biblatex/blob/c89dfc81e592de66eac0b9fe84b51eb973d42102/doc/latex/biblatex/biblatex.tex#L482) と同リビジョンの `blx-dm.def` を基に `src/biblatex-fields.json` へ保存しています。必須の分類は追加操作の案内であり、不足していても変換を阻止しません。カスタムスタイルによって必要な項目は異なります。abstract・keywords・file・note等を除去し、`_notes` は保持します。`addendum` 等の有効な任意フィールドも保持します。
